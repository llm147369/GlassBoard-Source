# 背景污点修复报告

- 项目：GlassBoard（C# / WPF / .NET Framework 4.8，全代码构建 UI，无 XAML）
- 排查范围：Dock 栏（`DockWindow`）、大面板（`BoardWindow`）、灵动岛（`IslandWindow`）及其共享基类管线 `GlassWindow`
- 结论：三类组件共用一套"截屏 → 烘焙 → 贴回"的毛玻璃底图管线，污点由该管线中 **7 个缺陷叠加** 造成。已全部修复，Release 编译通过（0 错误）。v2：自动刷新改为桌面层渲染（`PrintWindow`），刷新全程不可见；v3：壁纸文件直读取代截屏；v4：重捕原地更新底图不闪帧、Dock 外观预览不重建图标、组件定时器只改变化内容、彻底移除整屏截图回退。

---

## 一、毛玻璃背景的实现机制

GlassBoard 不使用系统亚克力，而是自绘毛玻璃：

1. `GlassWindow.CaptureRegion`：捕获窗口背后桌面壁纸的一块物理像素区域。v2 起优先用 `PrintWindow` 直接渲染桌面壁纸层（Progman/WorkerW），不可用时回退 `CopyFromScreen`；
2. 缩小为 1/8 小图并烘焙高斯模糊（`GlassMaterials.BoxBlur`），PNG 往返后作为 `ImageBrush` 贴到 `Root` 最底层（`Tag="backdrop"` 的 Border）；
3. 窗口 `AllowsTransparency=true`，透明区域透出的是这张"壁纸底图"，形成毛玻璃观感。

因此，**凡是捕获时把不该捕的东西（窗口自身残影、旧位置残影、条纹）烘进了底图，或显示时底图被拉伸/错位/堆叠，用户看到的就是"污点"**。

## 二、根因清单（7 个）

### 根因 1：可见态重捕"移窗后立即截屏"，窗口残影被烘进底图 ★最关键

**文件**：`src/GlassBoard/GlassWindow.cs`（旧 `RecaptureBackdrop`）

**现象**：Dock 拖拽落位、壁纸更换、前台窗口变化后，底图里出现一块半透明色斑/重影。

**原理**：窗口在屏幕上可见时无法原地截屏（会捕到自己）。旧实现把窗口 `Left/Top` 移到 `-20000` 后**立即** `CopyFromScreen`。但移窗只是发了一次 SetWindowPos，桌面合成器（DWM）还没提交"窗口已消失"的新帧——此时截屏，抓到的仍是窗口消失前的旧画面：窗口自身的半透明材质残影、拖动前旧位置的残影，全被烘进新底图。每次重捕，污点跟着壁纸底图一起被保存、显示，直到下次成功重捕才会消失。

**修复**：新增 `RunOffscreen`（异步版，`GlassWindow.cs:686`）与 `RunOffscreenSync`（同步版，`GlassWindow.cs:729`）：移窗后启动 120ms 定时器 / `PushFrame` 泵 120ms 消息循环，等 DWM 提交合成帧**再**截屏；截完移回原位并刷新样式。同步版供"必须拿到干净底图才能继续"的路径使用（灵动岛展开前）。**v2 起该路径仅为回退方案**：主路径改为桌面层渲染（见第八节），窗口原地不动，刷新完全不可见；只有桌面层渲染不可用（如 Wallpaper Engine 动画壁纸）才走离屏回退。

### 根因 2：黑帧判定阈值 1，深色壁纸被误判为"捕获失败"

**文件**：`src/GlassBoard/GlassWindow.cs`（旧 `CaptureRegion`）、`src/GlassBoard/IslandWindow.cs`（旧 `CaptureBackdropAllowDark`）

**现象**：使用深色/纯黑壁纸（或壁纸本身有大片深色区域）时，背景底图不更新、或显示成一块深色污块。

**原理**：截屏完成后用 8 个采样点判定是否捕到"黑帧"（截屏失败/窗口闪烁导致），旧阈值是 `R|G|B >= 1`。深色壁纸的像素通道值常低于 1，被误判为黑帧 → 底图不更新，旧底图与窗口错位显示，形成深色污块。

**修复**：
- 阈值提高到 `>= 4`（RGB 任一通道大于等于 4 即视为有效像素）；
- 采样由 8 点扩为 **8×8=64 点网格**（旧代码 `i==j` 只测了 8 个对角点，残影若落在非对角区域会漏检）。

### 根因 3：单步 Bilinear 缩小造成混叠条纹

**文件**：`src/GlassBoard/GlassMaterials.cs`（旧 `Downsample`）

**现象**：壁纸含高频细节（细纹理、文字、栅格）时，背景出现锯齿条纹/马赛克斑块。

**原理**：捕获大图用 `new Bitmap(src, w/8, h/8)` 一步缩到 1/8，默认插值是单步 Bilinear——高频细节混叠。小图贴回窗口 `Stretch.Fill` 拉回原始尺寸后，混叠纹被放大成肉眼可见的条纹。

**修复**：`Downsample`（`GlassMaterials.cs:95`）改为两级高质量缩小：只要目标尺寸仍大于源图的 1/4，先逐步半尺寸预缩，最后一步用 `InterpolationMode.HighQualityBicubic` 高质量插值到目标。模糊关闭（`MaterialBlur < 6`）时，灵动岛管线改为**按原始分辨率捕获、不缩小**（`IslandWindow.cs:3978`），彻底消除缩小-拉伸的马赛克。

### 根因 4：底图/材质层不做圆角裁剪，直角残影溢出圆角

**文件**：`src/GlassBoard/GlassWindow.cs`（旧 `AddBackdrop`、`SetGlassOpacity`）

**现象**：组件圆角外侧露出一条直角边纹理（尤其是开启 gloss/grain 材质时）。

**原理**：WPF `Border.CornerRadius` 只裁剪边框绘制，**不裁剪其子内容与 Background**。底图层与材质层（gloss 渐变、grain 噪点）都是直角矩形内容，四角必然溢出圆角。另外旧底图 Border 用的是 `Surface.CornerRadius` 的对称圆角，与灵动岛"吸附模式上圆角、悬浮模式下圆角"的真实外形不一致。

**修复**：新增 `BackdropClip()`（`GlassWindow.cs:787`）：按 `Root.Margin` 内容区计算宽高，用 `IslandChrome.RoundedRect(w,h,tl,tr,br,bl)`（`IslandChrome.cs:177`，四角独立圆角）生成显示裁剪区——**与捕获源区同源、与真实外形一致**。该 Geometry 应用到：底图外层 Border、底图内层 Border、材质层 Border（`RefreshBackdropStyle`，`GlassWindow.cs:806`；`SetGlassOpacity`，`GlassWindow.cs:882`）。

### 根因 5：底图层堆叠 + SetGlassOpacity 双路径 bug

**文件**：`src/GlassBoard/GlassWindow.cs`（旧 `AddBackdrop`、旧 `SetGlassOpacity`）

**现象**：窗口反复显示/隐藏后背景"越来越深"、出现多层重影。

**原理**：两个叠加缺陷：
1. 缓存命中路径（`cachedBackdrop != null && backdropKey == key`）直接 `AddBackdrop`，不清理已挂载的旧底图 Border——每次显隐堆一层，多张半透明壁纸底图叠在一起；
2. `SetGlassOpacity` 在"未应用过"分支调 `RefreshBackdropStyle()`，`RefreshBackdropStyle` 内部第一个动作是调 `Backdrop(LightTheme)` 重捕底图——随后又把 `materialSig` 更新为新签名。下次再进 `SetGlassOpacity` 时签名命中、`glassApplied` 为真，**走"未变化"短路路径，`RefreshBackdropStyle` 永远不再执行**——上一次重捕后的新底图 Border 永远不会被同步新的裁剪/圆角/透明度。Dock 的 `Build(capture:false)` 路径正是走这个流程。

**修复**：
- `AddBackdrop`（`GlassWindow.cs:758`）挂载新底图前先 `RemoveBackdropBorders()` 摘掉所有旧底图；
- `SetGlassOpacity` 的首次分支不再通过 `RefreshBackdropStyle` 间接重捕，材质层直接设置 `Clip = BackdropClip()`（`GlassWindow.cs:882`）；
- Dock `Build` 的 `capture:false` 分支改为 `SetGlassOpacity` + 显式 `RefreshBackdropStyle()`（`DockWindow.cs:954-959`）。

### 根因 6：灵动岛收起/展开状态错位，展开区底图被收起条小图替换

**文件**：`src/GlassBoard/IslandWindow.cs`

**现象**：灵动岛展开时背景模糊不清、像马赛克；收起后再展开背景出现深色/错位污块；设置页调整时岛会闪。

**原理**：灵动岛有两条底图管线：
- 收起态：基类 `GlassWindow` 管线，捕"收起条"区域；
- 展开态：岛自己的 `CaptureBackdropAllowDark`，捕"展开面板"区域，并把 `cachedBackdrop/backdropKey` 换成展开区。

缺陷链：基类管线（壁纸广播、前台窗口变化等触发的 `RecaptureBackdrop`）在收起态重捕后，`cachedBackdrop` 被替换成**收起条小图**；下次展开时直接复用这张小图拉伸铺满大面板 → 脏层。反过来展开态下基类 `Backdrop` 因缓存键对不上又会反复触发移窗重捕 → 设置页实时预览时窗口反复闪到屏幕外。旧的展开前重捕还有"移窗后立即截屏"（根因 1）和"阈值 1 误判深色壁纸"（根因 2）问题。

**修复**：
- 新增 `expandedBackdropStale` 状态机（`IslandWindow.cs:155`）：**任何基类底图重捕后一律标记展开底图过期**（`Backdrop` override，`IslandWindow.cs:3895`；`RecaptureBackdrop` override，`IslandWindow.cs:4025`）；
- 展开前若过期，`RefreshExpandedBackdrop`（`IslandWindow.cs:3860`）先用桌面层渲染**原地**同步重捕展开区域（v2 起刷新不可见），失败才回退 `RunOffscreenSync` 等 120ms 合成帧截屏；成功才显示面板，杜绝小图拉伸闪现；
- `CaptureBackdropAllowDark`（`IslandWindow.cs:3935`）：捕获区四周收缩 14px（避开自身边缘描边）、黑帧阈值 4、低模糊按原分辨率捕获（根因 3）、**成功后同步基类 `cachedBackdrop/backdropKey`**（`IslandWindow.cs:4009`）——展开态下基类 `Backdrop` 校验键匹配后只刷样式，不再触发反复移窗重捕；
- 旧的重试路径（4 秒定时器）改为 `RunOffscreen(() => CaptureBackdropAllowDark(rect))`（`IslandWindow.cs:3825`），同样等合成帧。

### 根因 7：模糊未烘焙进底图，运行时挂 BlurEffect

**文件**：`src/GlassBoard/GlassWindow.cs`（旧 `AddBackdrop`）

**现象**：背景色阶断层（banding）、模糊调高无效果、动画时卡顿。

**原理**：旧实现把模糊留在运行时：底图 Border 上挂 WPF `BlurEffect`。透明窗口上的 GPU 高斯模糊会产生色带/色阶断层；模糊程度变化时底图没有重烘，"调高模糊完全无效"；动画期每帧改变图层尺寸会触发整层重渲染，拖僵动画。

**修复**：
- 模糊已全部烘进底图（`GlassMaterials.BoxBlur` 两遍均值模糊），`AddBackdrop` 运行时不再挂任何 `BlurEffect`（`GlassWindow.cs:773` 注释明确）；
- `SetMaterial`（`GlassWindow.cs:114`）在可见状态下会 `ScheduleBackdropRefresh`，模糊半径变化 → 缓存键失效 → 按新半径重捕重烘。

## 六、不可见刷新（v2）

用户反馈：自动刷新会让组件闪烁/消失一下，影响美观。v2 把"移窗离屏截屏"从主路径降级为回退路径，主路径改为 **桌面层渲染捕获**，刷新全程无任何可见变化。

### 原理

DWM 合成桌面时是分层渲染的：壁纸画在桌面窗口（Progman/WorkerW）自己的渲染树里，GlassBoard 的悬浮组件是独立顶层窗口，**不在桌面窗口的渲染树中**。所以只要用 `PrintWindow(PW_RENDERFULLCONTENT)` 直接渲染桌面窗口的内容，得到的就是"只有壁纸、没有组件自身"的干净底图——窗口原地不动，不需要隐藏、不需要移屏，用户看不到任何闪烁。

### 实现（`src/GlassBoard/GlassCapture.cs`）

1. `FindWallpaperWindow()`：`FindWindow("Progman")` → `SendMessageTimeout(0x052C)` 生成 WorkerW → 枚举 WorkerW 的子窗口找到带 `SHELLDLL_DefView` 的宿主，取其下一个 WorkerW 兄弟作为壁纸层；找不到时退化用 Progman 本身；
2. `TryCapture(rect)`：按 `GetSystemMetrics(76-79)` 取虚拟屏幕物理像素创建整屏 Bitmap → `PrintWindow(hwnd, hdc, 0x2)` 渲染壁纸层 → `DrawImage` 裁出目标区域 → 8×8 网格阈值 4 判定空白帧（与底图管线同一标准）；
3. **Wallpaper Engine 检测**：存在 `wallpaper32/wallpaper64` 进程时直接返回 null（其壁纸是覆盖桌面层的独立窗口，打印结果是空帧，走回退路径反而正确）；
4. 失败一律返回 null，调用方保留现有底图（v4 起不再回退 `CopyFromScreen`，整屏截图路径已彻底移除），旧底图持续显示。

### 触发点（刷新现在都是不可见的）

拖拽落位、壁纸/显示设置变化、前台窗口切换、材质/模糊设置变更、灵动岛展开前——这些时刻组件**原地**换底图，画面只会有模糊内容的细微变化，不会有闪烁、消失或位移。

### 行为变化与权衡

- 底图内容变为"纯壁纸"：桌面图标、其他窗口不再被糊进背景（对毛玻璃来说这正是干净底图；v1 的离屏截屏同样捕不到被窗口遮住的内容，图标残留反而是旧管线污点来源之一）。
- 动画壁纸（Wallpaper Engine 进程模式）：v4 起保留最后一张干净底图，不再离屏截屏（支持边界见第八节）；未开 WE 则永远走壁纸直读主路径。
- Lively 等把动画画在 WorkerW 内的壁纸引擎正常走主路径，不可见且内容正确。
- 锁屏/桌面未就绪时打印结果判为空帧，自动重试（4 次）后保持旧底图，不闪烁。

## 七、权衡说明

- 壁纸直读/壁纸层渲染主路径零可见影响；两者都不可用时保留现有底图（无离屏路径），代价是动态壁纸（WE）下底图不跟随动画更新。
- 灵动岛展开前同步重捕会阻塞 UI 约 120ms（`PushFrame`），换取的是展开瞬间不出现脏层闪现；捕获失败（黑帧）时岛仍按原逻辑降级显示。

## 八、干净背景直读（v3）

用户追问：为什么不能"直接获取背景"？为什么还会捕获到组件上层的东西？Dock 栏上面为什么一直有显示？v3 给出机制级答案。

### 为什么旧管线会捕到"组件上层的东西"

截屏类管线（`CopyFromScreen`）和桌面层打印（`PrintWindow`）取到的都是**屏幕上/桌面窗口里正在显示的像素**：

- 离屏截屏依赖"先把窗口移出屏幕"：移窗是异步的，DWM 合成帧晚于截屏到达时，抓到的就是窗口消失前的旧画面（组件自身、其他窗口的残影）——这是"捕获到组件上层东西"的直接来源（根因 1）；
- 桌面层打印取到的是壁纸层渲染树，虽然排除了悬浮组件，但**Windows 把"更换壁纸"做成异步文件替换 + 广播**，若在替换间隙打印，会拿到上一次壁纸；它也不是"壁纸文件本身"，而是一帧渲染结果。

两者都是"截屏思想"：**抓屏幕，而不是拿数据源**。屏幕上有谁，谁的影子就可能混进来。

### v3：壁纸文件直读——从数据源拿背景

`src/GlassBoard/WallpaperSource.cs` 通过 Windows Shell 的 `IDesktopWallpaper` COM 接口拿到每个显示器**当前壁纸的文件路径、摆放方式（填充/适应/拉伸/居中/平铺/跨屏）和背景色**，再用 GDI+ 按摆放方式把目标屏幕矩形精确映射成壁纸源图区域渲染出来：

| 摆放方式 | 映射公式 |
|---|---|
| 填充 Fill（默认）/跨屏 Span | 等比放大至铺满，居中裁掉超出部分 |
| 适应 Fit | 等比缩放至完整显示，空白处填背景色 |
| 拉伸 Stretch | 直接拉伸变形铺满 |
| 居中 Center | 原始尺寸居中，四周填背景色 |
| 平铺 Tile | 按图块尺寸铺满 |

- **任何窗口、图标、悬浮层都不可能混入**：这不是屏幕像素，是壁纸文件本身。Dock 上"一直有显示"的残影（旧底图烘进的重影）在第一次重捕后即被干净底图替换，且此后每次捕获都是文件源，不可能再烘进新东西；
- **原地完成**：不截屏、不移窗、不等合成帧，刷新零可见，也没有黑帧（文件不会"锁屏变黑"）；
- **与"设置什么样式就什么样式"对齐**：捕获后统一走 `GlassMaterials.Bake`（`GlassMaterials.cs:220`）——模糊关闭/很小时保留原分辨率，否则 1/8 高质量缩小 + 盒式模糊烘进小图，运行时不再挂 `BlurEffect`。Dock、大面板、灵动岛三条管线共用同一烘焙数学，样式设置与显示效果一一对应。

### 捕获决策链（`GlassCapture.Acquire`，`GlassCapture.cs:39`）

```
壁纸文件直读（WallpaperSource）
  ├─ 成功 → 底图（fromFile=true，跳过黑帧重试）
  └─ 不可用（动态壁纸进程 / 无文件 / 接口失败）
      └─ 壁纸层渲染（PrintWindow，多候选 WorkerW + 纯净度校验）
           ├─ 与文件渲染一致（干净）→ 底图
           ├─ 被宠物/悬浮窗污染 → 直接用壁纸文件的静态渲染
           └─ 无可用层且无静态参考 → 保留现有底图（绝不整屏截图）
```

动态壁纸的处理（`WallpaperSource.cs:318` 进程检测 + `GlassCapture.cs` 纯净度校验）：

- **Wallpaper Engine（wallpaper32/64 进程）**：壁纸文件只是静态垫底图，动画画在独立覆盖层 → 文件直读放弃；壁纸层渲染出的静态垫底图与文件渲染一致（纯净），底图 = 干净的静态垫底图，换壁纸后跟随更新（支持边界：动画内容不进底图，但覆盖层实时播放不受影响）；
- **Lively**：动画画在 WorkerW 壁纸层内 → 文件直读放弃（垫底图 ≠ 所见），壁纸层渲染与静态参考大面积不同 → 判为实时动画层采用，零可见且内容正确；若差异接近全域（宠物自建 WorkerW/黑帧）则回退静态渲染。

### 兜底与缓存

- 显示器矩形异常时按系统 DPI 归一（`WallpaperSource.cs:287`），保证与 `GetWindowRect` 同一物理坐标系；
- 壁纸文件加载后带 EXIF 方向归一（手机竖拍直接设壁纸的文件方向是横的，`WallpaperSource.cs:246`）并缓存（最多 4 张全分辨率图）；
- Windows 7 无 `IDesktopWallpaper` 时 COM 创建失败 → 自动降级壁纸层渲染，功能不缺失；
- 黑帧重试只对"渲染类"来源生效（文件源无黑帧概念），避免黑色壁纸被误判重试风暴。

### 重构后的代码结构

| 模块 | 职责 |
|---|---|
| `WallpaperSource` | 壁纸文件 → 任意屏幕矩形区域（数据源层，纯 GDI+） |
| `GlassCapture` | 获取链编排 + 壁纸层渲染（`Acquire`/`TryCapture`），不可用即返回 null |
| `GlassMaterials.Bake` | 统一样式烘焙（模糊/缩小/PNG 往返），基类与灵动岛共用 |
| `GlassWindow.CaptureRegion` / `IslandWindow.CaptureBackdropAllowDark` | 各自窗口的裁剪/黑帧判定/缓存键/挂载，均经 `Acquire` + `Bake` |

至此背景体系回答用户的三个问题：**为什么不能直接获取背景**——现在就是直接拿壁纸文件；**为什么还会捕获到上层的东西**——截屏管线已被文件直读取代，从机制上不可能；**Dock 栏上面一直有显示**——旧底图烘进的窗口重影，第一次重捕后被干净底图替换。

## 九、无残影与不闪烁加固（v4）

针对新一轮"检查并修复底图混入窗口内容、组件/灵动岛/大面板/Dock 闪烁刷新"的要求，逐条核对捕获管线与刷新路径，共修 4 处。

### 9.1 重捕不再"先摘后挂"，底图原地更新（验收：刷新不消失）

**问题**：`GlassWindow.CaptureRegion` 捕获成功后、`AddBackdrop` 之前先调 `RemoveBackdropBorders()`，把正在显示的底图层整个摘掉再新建——每次重捕中间都有一帧背景消失（闪烁帧）。且新建分支的局部变量 `element` 与查找分支的局部变量重名，产生 CS0128 编译错误。

**修复**：删除该提前摘除；`AddBackdrop`（`GlassWindow.cs:520`）统一为"先找既有底图层（`Tag=="backdrop"` 且子节点为 Border）→ 原地替换 `ImageBrush`/裁剪/圆角/透明度 → 清理重复层"，仅首次（无既有层）才走新建分支。重捕全程画面连续，旧底图保留到新底图就绪。

### 9.2 Dock 外观预览不重建图标（验收：预览不销毁重建）

**问题**：设置页实时预览计时器每个 tick 调 `Dock.Refresh(capture:false)`，该方法无条件 `Items.Children.Clear()` 后整排重建 `DockButton`——透明度/模糊滑块连续拖动时，整排图标被反复销毁重建：闪烁，且打断"图标后台提取 → 回填"管线（新按钮回填完成前显示占位符）。

**修复**：
- `DockWindow.RefreshAppearance(bool capture=false)`（`DockWindow.cs:971`）：只更新 `ConfigureGlass` 玻璃参数、菜单主题、`Items.Margin`、圆角、宽高、玻璃透明度与底图样式（`SetGlassOpacity` + `RefreshBackdropStyle`）、边框色——**不触碰 `Items` 子节点**；
- `Refresh` 保留结构重建语义（图标增删/顺序变化等低频事件），调用点不变；
- `Controller.cs` 外观预览计时器改调 `RefreshAppearance(capture:false)`。

### 9.3 触发面核对（验收：普通应用前台切换不重捕；消息合并）

- **壁纸/显示器/DPI**：`GlassWindow` 钩子只认 `WM_SETTINGCHANGE wp=SPI_SETDESKWALLPAPER(0x14)`、`WM_DISPLAYCHANGE`、`WM_DPICHANGED` → 全部进入 `ScheduleBackdropRefresh`（单定时器 1.2s 重置式去抖，连续系统消息合并为一次重捕）；
- **前台切换**：Dock 运行指示器路径（`OnRunningForegroundChanged`）只 `UpdateRunning`/`Scan`，不触碰底图、不重建图标；基类无前台切换钩子——普通应用切换焦点**不触发**重捕；
- **组件定时器**：`WidgetManager` 的 1s/30s 定时器只调 `widget.Tick()`，`WidgetWindow` 只对变化的文字 `SetText`；结构（尺寸/选项签名）变化才 `Build()`；
- **灵动岛展开/收起**：展开前 `RefreshExpandedBackdrop` 原地同步重读展开区壁纸（文件直读/壁纸层渲染），无移窗；壁纸变化经 `ArmWallpaperRedo`（4s 防抖）只做原地 `RecaptureBackdrop`。

### 9.4 彻底移除整屏截图回退（验收：底图不出现窗口残影）

壁纸文件直读与壁纸层渲染都不可用（如 Wallpaper Engine 覆盖层）时，`Acquire` 直接返回 null → 调用方**保留现有底图**。代码中已不存在整屏截图的执行路径，历史"移窗等合成帧截屏"代码已在前几轮清除；本轮把 `GlassCapture.cs`、`WallpaperSource.cs`、`GlassWindow.cs`、`IslandWindow.cs`（含多处乱码注释）、`IslandHub.cs`、`Native.cs` 中描述旧行为的注释统一改为现状，避免后续维护被误导。

### 9.5 本轮其他修复

- 修正 `AddBackdrop` 新建分支局部变量与查找分支重名导致的 CS0128（改名为 `wrapper`）；
- `GlassCapture.FindWallpaperWindow` 只在 Progman 存在时才认 DefView 之后的 WorkerW，避免把桌面图标层（SHELLDLL_DefView 所在窗口）当成壁纸层。

- `dotnet build -c Release` → **0 错误**，12 个既有无关警告（`SystemMedia.cs`/`IslandLyrics.cs` CS0649、`BoardWindow.cs:73/128` CS0414），产物 `src\bin\Release\net48\GlassBoard.exe`；

## 十、壁纸层纯净度校验（v5）

用户反馈：桌面小宠物放到组件上时"一直显示阴影"——组件下面总有一层宠物图像的残影，宠物挪走后仍在，且残影显示在组件玻璃的下方。

### 残影从哪来

壁纸层渲染取的是"画在壁纸 WorkerW 里的像素"。桌面宠物类软件两种做法都会污染底图：

- 把宠物**直接画进壁纸 WorkerW**（画在壁纸图层里，位于桌面图标之下、所有正常窗口之下）→ `PrintWindow` 连同宠物一起采进底图；
- **自建一个 WorkerW** 当"宠物图层" → 旧逻辑"取 DefView 宿主之后紧跟的 WorkerW"可能正好选中宠物图层，把宠物图层整层当壁纸采进底图。

底图拿到宠物像素 → 统一 `Bake` 模糊 → 组件玻璃下面永久糊着一团宠物形状的暗影，直到下次成功重捕。这就是"在上面有一层、在组件下面显示"的真相：那是底图里烘进去的宠物重影，不是宠物本身。

### v5：纯净度校验（`GlassCapture.cs`）

壁纸文件是"干净标准"。`WallpaperSource.RenderStatic(rect)` 不受动态壁纸门控，任何时刻都能渲染出壁纸文件在指定矩形应有的样子。校验流程：

1. **枚举候选**：DefView 宿主之后的 WorkerW 优先，其余顶层 WorkerW 兜底（最多 3 个）；
2. 每个候选各自 `PrintWindow` 渲染目标矩形，与 `RenderStatic` 参考图做 **32×32 网格均值差**（平均格差 / 差异格数 / 最大格差）；
3. **决策**：
   - 静态壁纸：干净候选 = 差异格数 ≤ 6%（61/1024）且最大格差 ≤ 24 → 采用；否则判为被污染 → 丢弃捕获，直接返回壁纸文件的干净渲染；
   - 动态壁纸（Lively/WE）：差异格数 ≤ 95% 判为实时动画壁纸层 → 采用；几乎全域不符（宠物自建 WorkerW、黑帧残留）→ 丢弃，回退静态渲染；
   - 无静态参考（COM 异常）时取首个可用候选（兼容旧行为）。
4. 被拒绝的路径只返回"壁纸文件渲染"或 null，**绝不整屏截图**。

### 效果与边界

- 宠物画进壁纸层 → 底图 = 文件渲染的干净壁纸；宠物本身是真实窗口，仍实时显示在组件玻璃下方，但永远不会烘进底图；
- 宠物自建 WorkerW → 被"与文件渲染最接近"的多候选规则自动排除；
- 现有残影：下次重捕（换壁纸/拖拽落位/重启）即被干净底图替换；
- WE 用户底图从"保留旧图"升级为"干净的静态垫底图"，换壁纸后底图跟随更新（动画覆盖层实时播放不受影响，只是不进底图）；
- 边界：Lively 实时层与静态参考差异超过 95%（壁纸文件与动画内容完全不同）时，底图回退静态渲染、不跟随动画；无静态参考且无可用 WorkerW 时保留现有底图。
